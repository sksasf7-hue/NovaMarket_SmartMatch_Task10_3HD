Developer wiki / tutorial

How this feature was implemented

This concise tutorial is included directly in the website so another developer can understand and recreate the SmartMatch pattern.

01

Model useful product attributes

The PRODUCT table stores price, stock, rating, eco score, accessibility score, performance score, badge, description, and feature list. These fields give the ranking logic meaningful signals.

02

Collect clear preferences

The SmartMatch form captures category, budget, priority, and use case. Labels and keyboard-friendly controls keep the interface accessible.

03

Score with explainability

The server calculates category fit, budget fit, availability, priority match, and use-case fit. The API returns score breakdowns so the user sees why a product is recommended.

04

Render interactive results

JavaScript builds result cards, progress bars, reason chips, wishlist buttons, and comparison controls. Results are updated without reloading the full page.

05

Persist user actions

Recommendation runs, contact messages, added products, and wishlist clicks are stored in SQLite using parameterized SQL and server-side validation.
